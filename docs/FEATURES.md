# Features

Every feature of prompt section 1 item 3, with the headless scenario that reaches it, the
`--dump-frames` hash of its first stable frame and its status. Statuses: **reached headless**
(a headless scenario of the port reaches it; nothing is claimed about its appearance),
**agent-observed**, **oracle-compared**, **user-confirmed**, or **not reached**.  A row's
scenario is the first `tests/harness/scenarios.py` run (in that file's order) whose event trace
has the row's match in `tests/harness/features.map`; its frame is that run's first stable frame
after the event (`tests/harness/features.py`).  Rows reached only from an edited save or under
the harness's 16-colour test switch say so: those inputs are test input, and nothing about the
original follows from them. "Looks the
same" is claimed only for oracle-compared or user-confirmed rows; there are none yet for the game itself
(the extension's DOS-profile rows at the end say what their user confirmation covers).

Frame hashes are the harness's SHA-256 of a present: the 640x480 virtual screen (one physical
palette index per pixel) followed by the 768-byte system palette (`tests/headless/host_headless.c`
`host_present`). They are port output, not original-game fixtures.
