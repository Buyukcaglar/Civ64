# Running civ64

`civ64.exe` is a native Windows x64 port of the pinned Win16 *Sid Meier's Civilization for
Windows* (`civ.exe`, 832,512 bytes, SHA-256
`a66ec64020f10adb81613964f3d08a11ea278b6a5a060c8e49d1ea1fd3ba1788`). It contains no original
bytes: it reads the game's program and data from your own copy at run time. The port and its
sources stay local and unpublished. The program's file and product version are **1.0** (Explorer:
right-click `civ64.exe` > Properties > Details; product name "Sid Meier's Civilization 64bit", original
filename `civ64.exe`).

## Requirements

* Windows 10 (version 1607 or later) or Windows 11, x64 (civ64 uses the per-monitor DPI functions
  GetDpiForWindow and AdjustWindowRectExForDpi).
* Your own Civilization for Windows files, with the pinned `civ.exe` and its data files (the
  `.rsc` and `.wav` files, `civfonts.fon` and the others of the installation).
* The VGA system font `Fonts\vgasys.fon` in the Windows directory (part of every Windows
  installation; civ64 reads it, never installs it).

## Building

```
cmd /c C:\Projects\Civ1RE\claude\port\build.cmd
```

makes `claude\port\build\x64\Release\civ64.exe` (MSVC, x64, `/MT`). `build.cmd checked` and
`build.cmd asan` make the test variants; `test.cmd [checked|asan]` runs the tests. `build.cmd checked
noobs` makes the Checked variant with the presentation observer compiled out (`CIV_OBSERVER=0`;
programs in `build\x64\CheckedNoObs`, objects in `build\obj\CheckedNoObs`), and `test.cmd checked noobs`
tests it; it is the build in which the observer, the probes, the DOS profile and the switching do not
exist (see "Harness options for presentation and input" below).

```
cmd /c C:\Projects\Civ1RE\claude\port\build.cmd all
```

(since unit CY, `ext-CY-record.md` section 4) runs the generation steps and the clang-tidy probe once,
then builds `checked`, `checked noobs` and Release at the same time (through `tests\harness\testpar.py
build-all`), with the same outputs as the three single-variant builds. Each variant's output goes to
`build\build-all-<variant>.log` (printed in that order), and its tool logs carry the variant in their name
(`build\cl-c11-<variant>.log`, `cl-c17-`, `tidy-`, `tidy-checks-`, `cl-host-`, `cl-test-`, `link-`,
`cl-harness-`, `cl-win32-`, `rc-civ64-`, `link-civ64-`); a single-variant `build.cmd [checked [noobs]|asan]`
is unchanged, with its usual log names. It ends with `BUILD_ALL Checked exit 0 S s, ...; wall S s` and
`BUILD_ALL_OK variants=Checked,CheckedNoObs,Release`, or with `BUILD_ERROR=build.cmd all: a variant failed`
(exit code 1). About 300 s on this machine (233 s at the BS phase gate, 2026-10-15), against about 750 s for the three builds one after another;
the phase gate's eight-step cycle may use it for its steps 1, 4 and 7. Inside one variant the sources
are still compiled one after another. (`--nogen` is internal to `build.cmd all`.)

## Tests

```
cmd /c C:\Projects\Civ1RE\claude\port\test.cmd [checked [noobs]|asan] [serial|parallel]
```

runs the headless tests of a variant built by `build.cmd` (Release without an argument) and ends
with `TESTS_OK` or `TESTS_FAILED`. It needs two hash-verified copies, which the tests only read:
`claude\port\build\gamedata` (the Windows game, with `civ.exe`) and, since extension phase D2,
`claude\port\build\dosdata` (the read-only copy of Civilization for DOS: 176 files, each equal to
`docs\dos\dos-hashes.txt`). Without either, `test.cmd` stops with `TEST_ERROR` (exit code 2).
`registry.py check` also reads the DOS listings in `claude\port\build\dos\disasm` (made by
`gen\dos\disasm.py`).

A later unit adds a `test.cmd` step as a section (`ext-CY-record.md` section 3, "How a unit adds a
section"): one line `rem @section NAME [after=NAME,...] [cpu=N] [est=SECONDS]` in the section list, at its
place in the sequential order, and its commands under the label `:sec_NAME`, ended by `goto :eof`, written
as the existing blocks (its marker line first, `set /a FAILED+=1` per failure). `after=` names every section
whose outputs it reads, or whose files or directories it also writes, cleans or reads (`after=*`: after
every earlier section, as `coverage`); `cpu=N` when it runs N processes at once; `est=` its time in seconds
(it only sets the first start order). Keep `test.cmd`'s CRLF line endings: cmd's label search is
unreliable in LF-only batch files, and `testpar.py check` refuses LF lines, which fails the run. Check the
list with
`C:\Python314\python.exe -B tests\harness\testpar.py check test.cmd` in `claude\port` (it prints nothing and
exits 0 when the list is good) and `testpar.py list test.cmd`. A new `test_*.c` needs no section: the `unit`
section runs every `test_*.exe`.

### Harness options for the DOS files

The headless harness `civ_harness.exe` (built for the Checked variants, including `checked noobs`, and
Asan) takes two options for the DOS files. Neither changes the run of the game.

| Option | Meaning |
|---|---|
| `--dos-data <dir\|zip>` | The DOS source, read only: a folder, or a ZIP file (a path ending in `.zip`), read into memory, of which the folder that holds its one `CIV.EXE` (else its one `CIV_UNP.EXE`) is used. The DOS asset store is built once, before the emulation starts, and its result is written to `<out>\dos-assets.log`. |
| `--dos-inject <NAME>:missing\|size\|error\|flip` | For tests, with `--dos-data`; repeatable, at most 8. The read of the file NAME (8.3, any case) reports a missing file, a different size or a read error, or (`flip`) succeeds with one bit changed, which the SHA-256 check then refuses. |

`dos-assets.log` has three lines:

```
dos_assets status <S> files <N> decoded <D> shapes <K> source <folder or ZIP>
failed_file <NAME, or ->
message <one sentence, empty when the store is ready>
```

S is the store's status: 0 ready, 1 no DOS source, 2 a file missing, 3 a size differs, 4 a SHA-256
differs, 5 a read error, 6 a file that cannot be decoded, 7 a data table that fails its check. When
it is ready, N is the number of required files (158), D the required pictures and palettes decoded
and K the shape entries filled; otherwise all three are 0. A `--dos-data` that is neither a folder
nor a ZIP with `CIV.EXE` or `CIV_UNP.EXE` gives status 1, an empty source and the note "(not a
folder or a ZIP with CIV.EXE)". The result goes only to this log, never to `run.log`, `events.log`,
`presented.log` or the summary line.

## Where civ64 finds the game

civ64 needs the files of Civilization for Windows (required) and can use those of Civilization
for DOS (optional, for the DOS graphics profile of later versions). Without `--data` it looks,
in this order (names compared ignoring case):

1. A ZIP file next to `civ64.exe` named `CivWin.zip`, `Civ-Win.zip` or `Civ_Win.zip`. Its files
   (those in the folder of the ZIP that holds `civ.exe`) are checked and extracted to
   `%LOCALAPPDATA%\civ64\CivWin`, which becomes the data directory. A later, changed ZIP updates
   the files you have not changed; your saves and changed files stay.
2. A folder `CivWin` next to `civ64.exe`.
3. The folder of `civ64.exe` itself, when it holds `civ.exe`.
4. The location you chose before (remembered in `civ64.cfg`).
5. Otherwise civ64 asks: choose the game's `civ.exe`, or a ZIP file of the game, in the Windows
   file dialog. A valid choice is remembered.

For the DOS version: `--dos-data`, then `CivDos.zip`, `Civ-Dos.zip` or `Civ_Dos.zip` (read, never
extracted), a `CivDos` folder, the remembered location, and otherwise a question that you can
answer "not now" or "don't ask again". A file or folder that is found but is not the right version
stops civ64 with a message that names it. To be asked again after "don't ask again", delete the
line `dos_ask=never` from `%LOCALAPPDATA%\civ64\civ64.cfg`; or put one of the ZIP files or the
`CivDos` folder next to `civ64.exe`, or start once with `--dos-data <folder or ZIP>`, which uses it
without remembering it. While the game runs, the window menu's **Graphics** > **Locate DOS files…** (since HM; before,
**Locate DOS files...** in the menu itself) records a location that is used from the next start (see "The graphics
profiles"); while the DOS files are present it reads **DOS files present**, gray.

The opening credits, intro, title menu, Birth scenes and setup screens keep the original's 640x480
(4:3) picture, with black borders in a wider window. When the game itself begins (a new, loaded,
EARTH or customized game), the game's screen takes the window's size at the current scale, so the
map uses the whole window: with a 1920x1080 window at twice the size, the game screen is 960x540
(FIDELITY F105). From then on the game screen follows the window: enlarge, shrink, maximize or
restore the window (or switch to full screen) while playing, and the game's screen grows or shrinks
with it at once, at the pixel size the game began with (smaller only when the window can no longer
hold 640x480 at it). The map window keeps the right and bottom edges it touches, the other windows
stay where they are or are moved back into a smaller screen, and you can arrange and size them as
you like (F110). The desktop around the game's windows is black (F107). The same seed plays the same
game only at the same game screen size (the map's dissolve draws random numbers per visible square).

civ64 remembers the window's position and size, and whether it was maximized, between runs (in
`civ64.cfg`; saved when you finish moving or sizing it, maximize or restore it, and when the game
ends). The first run opens a 4:3 window, the largest whole multiple of 640x480 that fits the primary
screen's work area, **centred** on it horizontally and vertically (F111). Later runs open the window
where you left it, at the remembered size. A window that is **entirely off-screen** (for example a
monitor was removed since, or the `window` line of `civ64.cfg` was edited off every monitor) comes back
at the top-left corner of the primary screen's work area; a window that is only partly off-screen, or
spans two monitors, stays where it was left. The `window` line is `window=left,top,right,bottom`: the window's
outer rectangle in screen pixels (the primary screen's top-left is 0,0; `right` and `bottom` are one past the
window, so the width is right - left). Since UX4 a remembered window stays where it was only while enough of its
title bar to drag it (about two title-bar heights wide, at least half its height) is on a screen's work area and
Windows can give it at its size; otherwise it comes back at that top-left corner, and closing civ64 writes the
rectangle the window really had back to `window` (F111). `--window` or `--scale k` give the first size
(the window is then centred as on a first run). The window's title bar reads "Sid Meier's Civilization 64bit"
(F106) and the About box is titled "About Sid Meier's Civilization 64bit v1.0" (F108). The title bar, the
window's system menu and its About box follow Windows' light or dark app
mode (Settings > Personalization > Colors) and change with it at once (F109); since UX4 so do civ64's own
message boxes (`hw_message_box`: the host's messages, the overwrite question, the notes and questions about the DOS
and Windows files, such as the DOS-files refusal of "Locate DOS files…"), with a dark title bar, text area and
buttons in dark mode.

At the start of a game the map, World Map and Status windows take the places saved in the data
directory's `civ.prf`. When those places do not fit the game screen or there is no `civ.prf`, all
three take the default layout: World Map 0,0..166,127, Status 0,126..166,458, and the map from x 165
to the screen's right and bottom edges (FIDELITY F103). A layout saved on a different screen size
follows the new size: windows that touched the right or bottom edge stay there (civ64.cfg's
`layout_screen` remembers the size the layout was saved on). The places and sizes you give the
windows are saved in `civ.prf` when the game saves its preferences (at exit) and kept; delete
`civ.prf` to get the default layout back (Game Options are saved in the same file).

To prepare a folder by hand, copy every file of your Civilization for Windows installation into a
directory of its own, for example `C:\Games\CivData`, and make the files writable (saves,
preferences and the Hall of Fame are written there). civ64 refuses to run in a directory whose
path ends in `original\CIVWIN`, so that the original installation of this project is never
modified.

**Alternative music and sound effects** (since AMS, FIDELITY F332..F334). civ64 can play your own music and sound
effects instead of the Windows game's 24 wave files (`ALEX.WAV`, `CANNON.WAV`, `OPENING.WAV`, ... the WAV files of the Windows
game's data; `verify/BRIEF-extras.md` lists them). After the DOS files it looks, in this order, at `--music-sfx <dir|zip|none>`,
a `MusicSfx.zip` next to `civ64.exe`, a `MusicSfx` folder there, and the source remembered as the `music_data` key of
`civ64.cfg` (names compared ignoring case). Without one, the first start asks after the DOS question, in the same way:
Yes opens the file dialog for a WAV file (its folder is the source) or a ZIP; No asks whether to ask again the next
time (No then writes `music_ask=never`). A source counts when at least one of the 24 names in it is a valid WAV file:
in a folder its top level, in a ZIP any one folder; each valid file is played instead of the game's file of that name
(any case), every other sound is the game's own. The files are read into memory at the start (a ZIP is never
extracted) and a change takes effect at the next start. The window menu's **Alternative music/soundfx** is checked
when a valid source is found or chosen; your uncheck or check is remembered as the `alt_sounds` key.

## Command line

```
civ64.exe [--data <dir>] [--dos-data <dir|zip|none>] [--graphics windows|dos]
          [--zoom default|-1|0|+1] [--fullscreen] [--window <W>x<H>]
          [--scale auto|1..8] [--scale-mode integer|fit] [--filter nearest|sharp]
          [--aspect square|4:3|gameplay|both] [--windowless 0|1] [--crt 0|1]
          [--music-sfx <dir|zip|none>] [--timing classic|host] [--dump-frames <dir>]
          [--dump-presented <dir>] [--multi-instance]
```

| Option | Meaning |
|---|---|
| `--data <dir>` | The data directory; no lookup (see above). Its `civ.exe` must be the pinned version (size and SHA-256 are checked). |
| `--dos-data <dir\|zip\|none>` | The DOS version's folder or ZIP; `none`: not used, not asked. |
| `--graphics windows\|dos` | The graphics profile to start in. Without it: the profile you last switched to (the `graphics` key of `civ64.cfg`), else `windows`. `dos` needs usable DOS files: without them civ64 stops at once with exit code 2 and the sentence that names the problem, before the window opens. A remembered `dos` that is not usable starts `windows` without a message. The option is never remembered; only a switch you make in the running game is (see "The graphics profiles"). In this version the DOS profile shows the DOS intro and title box and otherwise the Windows picture (see "The graphics profiles"); since D6c the main map window's client in play shows the DOS map. |
| `--zoom default\|-1\|0\|+1` | The map zoom level for this run (see "The map zoom"): `-1` half size, `0` or `default` normal, `+1` double. Without it: the level you last chose (the `zoom` key of `civ64.cfg`), else `0`. Anything else (`--zoom 1` included) stops civ64 with exit code 2 and the usage. The option is never remembered; only a level you choose in the running game is. A build without the observer (`checked noobs`) refuses `--zoom` with a message box and exit code 2. |
| `--scale auto\|1..8` | The window's first size: a 640k x 480k client. Default `auto`: the remembered position and size, else the largest k up to 8 whose window fits the work area of the primary monitor (until LP: the monitor that holds the mouse pointer). A number takes the place of the remembered size for this run, and the window is centred in the work area. |
| `--window <W>x<H>` | The window's first client size instead (at least 640x480; not with `--scale k`); the remembered size is not used for this run, and the window is centred in the primary work area. |
| `--fullscreen` | Start in full screen. |
| `--scale-mode integer\|fit` | How the picture fills the window: `integer`, the largest whole multiple (sharp, black borders); `fit`, as large as the window allows with its proportions. Without it: your last choice, else `integer`. (`stretch` was removed: the game itself now fills the window, see below.) |
| `--filter nearest\|sharp` | For `fit`: `nearest` repeats pixels, `sharp` blends only the edges between them. Without it: your last choice, else `nearest`. |
| `--aspect square\|4:3` | For 320x200 screens (the DOS profile): the 4:3 shape of the DOS screen or square pixels, for this run only (not remembered). Without it: your choice in the window menu, else `4:3` (since UX3; square under UX2). Your menu choice is remembered as the `aspect_4_3` key of `civ64.cfg` (written only when you change the item); the `aspect` and `aspect_320x200` lines of earlier builds are ignored and removed at the next save. With the DOS graphics only Birth keeps square pixels under 4:3 (since UX5; since UX5b from its first picture, so the title's fade into Birth keeps the 4:3 shape and the shape changes while the screen is black); the intro, the title menu, Customize World, the Hall of Fame, Load, the setup pages and play take the 4:3 shape (before UX5 the intro and the title menu kept square pixels too, UX3). Pictures of other sizes, including everything the Windows profile shows, keep square pixels (F116). Since A43 (F326..F328) `square` and `4:3` set the intro item ("4:3 aspect ratio for 320 x 200 DOS intro screens") and leave the gameplay item off; `gameplay` sets only the gameplay item ("4:3 aspect ratio for 320 x 200 DOS gameplay": in the DOS graphics during play every picture, the menu bar, the World Map, the map, the Status window, the boxes and the in-play full-screen DOS scenes, takes the 4:3 shape; the Windows graphics are unchanged), `both` sets both. The gameplay item is off by default and remembered as the `aspect_play_4_3` key. |
| `--windowless 0\|1` | Since WL (F322..F325, F337, F338): windowless play on (`1`) or off (`0`) for this run only (not remembered). Without it: your choice in the window menu (the `windowless` key of `civ64.cfg`, written only when you change the item), else off. Under a build without the observer `--windowless 1` stops civ64 with exit code 2. |
| `--crt 0\|1` | Since CRT (F329..F331, F335): the "CRT scanlines" filter on (`1`) or off (`0`) for this run only. Without it: your choice in the window menu (the `crt_scanlines` key), else off. |
| `--music-sfx <dir\|zip\|none>` | Since AMS (F332..F334): the alternative music and sound effects from that folder or ZIP for this run (see "Alternative music and sound effects" above); `none`: not used, not asked. A source without one valid WAV file of the 24 names stops civ64 with a message naming them. |
| `--timing classic\|host` | Default `classic`: the game's clock advances only by the fixed costs of its polls (`DESIGN.md` 6), and the game waits for real time to catch up only where it waits. `host`: the game's clock follows the real clock, and the game sleeps only where it waits for input or for time to pass. In both, CPU-bound work such as world generation and the computer players' turns runs at full speed. |
| `--dump-frames <dir>` | An existing directory; every presented picture is written there as `frame-NNNNN.bmp` (an 8-bit BMP of the indexed screen with its palette). Meant for checks; a game writes thousands of frames. |
| `--dump-presented <dir>` | An existing directory; the picture shown, before scaling, written as `presented-NNNNN.bmp` (24-bit, numbered as the core frames) at every present while the visible profile shows the core frame, and as `tick-NNNNN.bmp` at each tick or view show while it does not (8-bit when the picture is indexed, else 24-bit). Since D4a the DOS profile's `tick-NNNNN.bmp` is 8-bit for its N frame (320x200) and 24-bit for its A frame. For checks. |
| `--multi-instance` | A test option: this run neither takes nor checks the single-instance lock (below); the automated tests' starts of civ64.exe (`tests\win32\drive_civ64.py`) pass it. Players do not need it. |

bar, or right-click the title bar). Since HM (2026-10-17) it reads, from the top: Windows' own **Restore**, **Move**,
**Size**, **Minimize** and **Maximize**; **Full screen** (shown with **Alt+Enter**); the three submenus **Display**,
**Map zoom** and **Graphics**, each opened by moving the pointer onto it; **About…** (the port's credits, its

filter** (gray under integer scaling, which never filters) and **Correct 320 × 200 to 4:3** (on by default; DOS Birth
stays square, and since UX5 the DOS intro and title menu follow it). **Map zoom** holds **Zoom out (half)**, **Normal
zoom** and **Zoom in (double)**, radio items that mark the level and show **Ctrl+Shift+Minus**, **Ctrl+Shift+0, Home**
and **Ctrl+Shift+Plus**, and the check item **Mouse wheel zooms map** (checked by default; uncheck it and the mouse
wheel does nothing over the map; see "The map zoom"). **Graphics** holds **Windows graphics** and **DOS graphics**

profiles"). The marks are current whenever a menu opens. A letter underlined in an open menu chooses its item; the
menu itself opens with the mouse (Alt, Alt+Space and F10 stay the game's). Since session E5 (2026-10-18/19)
**Display** reads: **Windowless play** (WL; in play the map, the World Map and the Status panel form one picture
without title bars, frames or scroll bars, the menu bar across its top since WL2 and the Status panel reaching its

over it), **Integer scaling (whole steps)**, **Fit to window**, the two filters, **CRT scanlines** (CRT; one fixed CRT

MusicSfx source is found or chosen, gray without one; uncheck it for the game's own sounds). All four are remembered. Before HM the same choices stood in one

again (until UX1 it was disabled and the menu had no Close, F112). **Alt+Enter** switches full screen on and off. civ64
remembers these choices in `%LOCALAPPDATA%\civ64\civ64.cfg` (with the game's locations); options on
the command line apply to that run only. civ64 reads no other registry key, INI file or
environment variable; the Windows file dialog that asks for the game's location keeps its own
list of recent folders. Test-only options (scripts, injected times) exist only in the headless
harness.

**Closing civ64** (since UX1, F160). The window's close button, the window menu's last item **Close** (until HM
**Exit Sid Meier's Civilization 64bit**) and **Alt+F4** all end civ64, and so does a close request from elsewhere (Task
Manager's End task). Before the game (the intro, the title menu, the Birth scenes and the setup screens) civ64
ends at once. In the game (from the moment the game's map window opens, for a new, loaded, EARTH or customized
game alike) a warning box titled "Sid Meier's Civilization 64bit" appears instead: "A game is in progress. If
you exit now, any unsaved progress will be lost.", with **Exit Anyway** and **Cancel**. **Cancel** has the focus
and is the default (Enter); Escape, the box's own close button and Alt+F4 on the box also answer Cancel, and the
game goes on unchanged. **Exit Anyway** ends civ64 at once. While one of civ64's own boxes is open (About, a
message, a file choice, the overwrite question, "Locate DOS files…") these commands do nothing. An exit writes
civ64's settings and the window's placement, as the game's own end does, and never saves the game: save first
through the game's File menu. The warning follows Windows' light or dark app mode, as the About box does. The
game's own File > Quit works as before.

**One civ64 at a time** (since SI, FIDELITY F189). civ64 runs once per Windows logon session. Starting it again
while it runs shows the original game's own message "Sorry! Only one game at a time!" (title "CIVILIZATION Error", the
stop sign, OK); after OK the running civ64 comes to the front (restored when minimized, at its size and place,
maximized or full screen again if it was; its open box in front of it if it has one), and the new start ends with
exit code 0, whatever its command line, changing nothing in the running civ64. The original game refused a second
game with that message and left the running one where it was; bringing it to the front is civ64's addition. When the
running civ64 is another program file (another folder), civ64's own box "Sid Meier's Civilization 64bit" says so
instead, naming the running one's folder and asking to close that civ64 before starting this copy; after OK the
running civ64 comes to the front. Close the other civ64 while this box is open, then press OK, and this copy starts.
A civ64 that has ended, normally or not (Task Manager's End task, a fault), never blocks the next start. Started
again in the first moment, before the running civ64 has loaded the game, the new start shows no message and only
brings the running one forward. Builds before SI do not check, so an older build started beside this one still opens
a second civ64; a civ64 run as administrator, or as another Windows user in the same session, may not be seen, and a
second civ64 then opens.

### The graphics profiles

**Ctrl+Shift+Backspace**, or the window menu's **Graphics** > **Switch graphics** (since HM), **Windows graphics** /
**DOS graphics**, switches the graphics profile. The switch applies at the next tick, with the whole picture redrawn; the window is
never resized. The radio mark shows the profile you chose at once, before the picture changes (and, since UX2,
from the start it marks the profile civ64 started in: the remembered one or `--graphics`), and a
second chord pressed before the tick takes the first back, so a quick double chord leaves the profile
unchanged. In this version (since D4b) the DOS profile shows the DOS intro (credits over the panorama,
the logo reveal and its dissolve), from the game's intro start at the DOS program's own pace, and then
the DOS title box, whose highlight follows the game's title menu (FIDELITY F145..F149). The DOS intro runs
on the game's time whether it is visible or not, so a switch during the intro shows it at the same
moment; a key during the intro ends both intros (the DOS one through its dissolve, about 2 s), and no
mouse pointer is shown during the DOS intro. Since D5c (2026-10-16) the DOS profile also shows the DOS program's
own setup pages after the Birth: the difficulty page (from the DOS Birth's end, also while the Windows Birth
movie still runs), the competition page and the tribe page, with an added "Go Back" row and, on the tribe page, a
"Custom." row, taking the DOS keys and the mouse (FIDELITY F162). Since D5d (2026-10-16) it also shows the DOS
name boxes for the tribe's name (after "Custom.") and the leader's name over the DOS setup screen, with the DOS
font and the blinking light-blue cursor cell, the field following the game's own text (a long name scrolls inside
the box; Ins inserts a space, Return or a left click accepts), and then the DOS introduction text: a white screen
with the ornamental border, the chosen difficulty's portrait, the leader's and the tribe's names and the starting

### The map zoom

The map zoom (DESIGN.md 12.9, FIDELITY F129, F130, F132) shows the map window's picture at half size
(level -1), as the game draws it (level 0) or at double size (level +1). Only the client of the game's
map window is zoomed; the small map (the World Map window), the status window and the World Map report are not.

shows (larger at -1, smaller at +1; at -1 near a pole it stops at the world's top or bottom edge), in both graphics,

(FIDELITY F185, F132). Since D6e (2026-10-17) the DOS graphics' own small map outlines the same area in white
(FIDELITY F131), and its squares do not change with the level either. It is drawn
over the scaled picture, only where the map window is visible (not over a window lying on it, nor over
the outline of a window move or size), in the Windows graphics and (since D6d) the DOS graphics. Since MZS
(2026-10-16/17) the part of the map under an open menu, a dialog or a window moved over it comes from the game's own
map picture, as the game repaints its map window, so menus, dialogs and moved windows look over the zoomed map as at
level 0 (before, with civ64's own window layout, a black block appeared beside them at -1 and +1, and dragging a
window at -1 showed a smaller copy of its outline; FIDELITY F190). It never changes what the game does (invariant

| The window menu's **Map zoom** submenu (since HM; before, the window menu itself) | **Zoom out (half)**, **Normal zoom** (until HM **Normal map zoom**), **Zoom in (double)**: radio items that mark the level. **Zoom in** is grayed while the level +1 is refused. A level chosen here zooms about the centre of the map. |
| `--zoom` | The level for this run (see "Command line"). |

At +1 the zoomed picture follows the active unit: when one of your units blinks or moves, the picture pans
the least that shows its square with a one-square margin. Since MZI (2026-10-16) each time the game sets its view (its
centring by C, its moving the view to the next unit or to a unit at the edge of its view, a click on the small map,
the scroll keys) the picture centres on the square the game centres on, even when the game's own view does not move,
and a different unit that becomes active is centred when the picture would have to pan to show it; a unit's own moves
keep the least pan, and a wheel or menu zoom's anchored point stays until the next such centring. The zoomed-in
picture never leaves the game's own view: once your civilization knows Map Making the game's view stops at the north
and south edges, so a unit within about 3 rows of them stays a little off the centre toward that edge (without Map
Making the game's view goes beyond the edges and the unit is centred; FIDELITY F185). At -1 the whole of the game's own view is shown
at half size inside its surroundings, which are drawn by the game's map rules from the latest state the
port copied at a redraw, a unit move or a turn; a **left click** on a surrounding square recentres the
game's map on it, as a click on the small map there would. Since MZ (2026-10-16) each time the game's view changes
at -1 (the game's centring by C, its automatic centring of the next unit, its scrolling, a click on a surrounding
square or on the small map) the picture centres on the game's view: the active unit's square is at the centre of
the map window in the middle of the map, roughly rows 15 to 35 of 50 (exactly from half the zoomed picture's height
from both poles); nearer a pole the unit stays off the centre toward it, because the zoomed-out picture shows no rows
beyond the poles (the pole limit the user kept; FIDELITY F185). After a wheel or menu zoom the anchored point stays
until the game's view next changes. A right click there, a click beyond the poles
and a click while the small map is hidden, iconic, disabled, covered or captured do nothing. A drag that
starts on a surrounding square and is released anywhere leaves no button held. At -1 with a whole-number
scale that is odd (the 1920x1440 window on a 2560x1600 display is a factor of 3) or 1, the squares line
up exactly but the pixels inside a square are uneven (F129).

+1 is refused (nothing happens; **Zoom in** is grayed) while the map window is too small to show 3 x 3
squares at double size, and a resize below that returns the level to normal. The level is kept when a
map window does not exist yet. civ64 writes the level to the `zoom` key of `civ64.cfg` (`-1`, `0` or
`1`; anything else reads as absent) whenever you change it with a chord, the wheel or the menu, and
reads it at the next start unless `--zoom` is given. The state of **Mouse wheel zooms map** (until HM **Mouse wheel
zooms the map**) is the
`wheel_zoom` key of `civ64.cfg` (`1` on, the default; `0` off; absent or anything else is ignored and
the wheel stays on); it is written only after you change the item and read at the next start. A build
without the observer (`checked noobs`) has no zoom: the menu items (the wheel item included) are grayed,
the keys are not chords, and `wheel_zoom` is neither read nor written.

## Playing

The game behaves as the original under Windows 3.1, with its own windows inside one host
window. Some host details:

* Any key during the opening credits skips to the title menu. At the title menu Enter takes the
  selected item; while the world is being created a key press skips the Birth scenes as soon as
  the world is ready.
* Alt and F10 open the game's own menus (not a host menu). Alt+Enter is civ64's full-screen key
  and never reaches the game. Since UX1 Alt+F4 is civ64's exit key (see "Closing civ64") and never reaches
  the game, nor does the Alt held for it; F4 alone still does. Ctrl+Shift+Backspace is civ64's graphics key (see "The graphics
  profiles") and never reaches the game, nor do the Ctrl and Shift presses held for it; Ctrl+Shift+Plus,
  Minus and 0 are civ64's map zoom keys (see "The map zoom") and are held back the same way, while the plain
  `=`, `-` and `0` reach the game. A click in the
  black border around the picture is ignored.
* A Ctrl or Shift press is held back until the next key event, like Alt: the game sees it late, just
  before the next key, or at its release when it is pressed alone (a lone Ctrl or Shift still skips the
  intro, at its release). Ctrl+Backspace, Ctrl+S, Shift+letter and the other accelerators work as
  before. While a Ctrl or Shift press is held back, mouse moves and releases do not carry its modifier
  flag; a click carries the flags as they are (F114). Since UX1 Alt+F4 and the host window's close
  button end civ64, at once before the game and with the warning box in the game (see "Closing civ64",
  F160); until UX1 they asked the game to close its active window, so the game's own Quit handling decided.
* Keyboard characters are taken from your keyboard layout and passed as Windows-1252; characters
  without a Windows-1252 code are dropped. While the game's NumLock is on (it switches it on at
  start), the numeric keypad gives digits whatever the host's NumLock state.
* Help (the original's `.hlp` file) is not available: Windows 10 and 11 have no viewer for it.
  Help > Game Help shows a message box that says so (F84).
* Sounds are the data directory's `.wav` files, played by Windows; a missing file is silent.

## Files written

Only in the data directory (and, with `--dump-frames` or `--dump-presented`, that directory), and
civ64's own folder `%LOCALAPPDATA%\civ64` (`civ64.cfg`; with a ZIP, the extracted `CivWin` folder and
its `CivWin.manifest`):

| File | Written by |
|---|---|
| saved games (`*.SAV`: the names you choose in the Windows chooser; `CIVILn.SAV` from an empty line of the DOS save screen) | Save Game |
| `civ.prf` | the game's preferences (Game Options) |
| `famehall.civ` | the Hall of Fame |
| `*.rep` | the replay at the end of a game, under the name you give in its Save dialog |
| `frame-NNNNN.bmp` | `--dump-frames` only |

## When civ64 stops

* civ64's own message boxes (the failures below, the "DOS files not found" and similar questions about
  the game's location, the out-of-memory and host-fault messages) are captioned "Sid Meier's Civilization
  64bit", like the window's title bar. The game's own dialogs keep the game's captions.
* **Closing civ64** with the window's close button, the window menu's **Close** (until HM **Exit Sid Meier's
  Civilization 64bit**) or Alt+F4 (in the game after **Exit Anyway** in the warning box; see "Closing civ64" above) ends with exit
  code 0, after writing the settings and the window's placement; the game is not saved.
* **A second start** while civ64 runs (see "One civ64 at a time" above) opens no window and ends with exit code 0
  after its message, or after its short wait when there is none to show.
* **Port-level failures** show a message box naming the cause, then civ64 exits with code 2:
  an unknown or malformed option; a data directory that is refused (`original\CIVWIN`), does
  not exist or cannot be read; a missing, unreadable or different `civ.exe`; a missing
  `--dump-frames` directory; the system font that cannot be read; a DOS folder that is the data
  directory itself (a folder inside it is accepted, F119); `--graphics dos` without usable DOS files
  (the message is the one sentence that names the problem; it is shown before the window opens); an
  invalid `--graphics` value; a window or drawing surface that cannot be created; a `civ.exe` that
  cannot be loaded.
* If the presentation observer cannot be set up at the start, civ64 ends with the message "The
  presentation observer could not be set up."
* **Faults of the original program** (for example an invalid selector or a stack overflow that
  would have stopped it under Windows 3.1) show "General protection fault (kind K) at
  SSSS:OOOO in statement SSSS:OOOO: ..." and exit with code 3 (`DESIGN.md` 3.3).
* Out of host memory: a message box, exit code 4.
* The original's own error messages and paths (missing data files, full disk, ...) are
  reproduced unchanged.

## Known deviations

[FIDELITY.md](FIDELITY.md) lists every place where the port does not, or cannot, reproduce the
original exactly, and every place where the original's behaviour is unknown. Among them: fixed
poll costs instead of the original machine's speed (F12), recorded machine values such as free
memory and display capabilities (F14, F25, F31), Windows 3.1's drawing of frames, menus and
controls (F26, F30, F76..F80), keyboard characters (F81), the host window's close box (F82; since UX1
the host's exit with its in-game warning, F160), the DOS pointer's size (F159), one civ64 at a time with the
running one brought to the front after the original's message (since SI, F189),
sound (F83), Help (F84). Same-seed equality with the original is not claimed.
