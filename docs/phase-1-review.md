## Findings

### B1. BLOCKER: push ds argument pushes and mid-body DS saves are generated as frame saves
(37 live functions)

- Where:
  - gen/frames.py, analyse() lines 61–71;
  - core/gen/civ_frames.c lines 26, 40, 61, 71, 98, 120, 206, 498, 683, 813 and the others
    listed below;
  - DESIGN 3.4 "Frame data".
- What is wrong:
  - analyse() treats every push si/push di/push ds directly after the prolog as a register save
    that the epilogue restores. For FR_FAR_BP and FR_BP frames it also treats a push ds right
    after mov bp,sp as push_ds.
  - It never checks the epilogue.
  - In this binary that push ds is usually the segment word of a far-pointer argument
    (DebugTraceFunction and strcpy string arguments). In six run-time functions it is a save
    that the body pops again before the return.
  - The generator still reports "0 unexplained", so the gate claim is not met.
- Evidence:
  - NewPtr 1100:05B8. The prolog ends with sub sp,6 at 05C2. Then 1100:05C5 push ds / 05C6 push
    offset aNewPtrMacC / 05C9 call far DebugTraceFunction / 05CE add sp,4. The epilogue is 0604
    lea sp,[bp-2] / pop ds / pop bp / dec bp / retf. Generated: FR_NewPtr = {..., FR_WIN_FAR,
    1u, 1u, 1u, {FRR_DS,0,0,0}, 0x6u}.
  - ApplyGlobalWarming 1028:1AFD. 1B0A push si / 1B0B push di / 1B0C push ds / 1B0D push offset
    aGlobalTemperature… / 1B10 push seg data_12D8 / 1B13 push offset g_messageText / 1B16 call
    far strcpy / 1B1B add sp,8. The epilogue is 1C9E pop di / pop si / lea sp,[bp-2] / pop ds /
    pop bp / dec bp / retf. Generated regs: {SI, DI, DS}.
  - The same pattern appears at PortTileBlt 11A8:045F (epilogue 05BE pop di; pop si; lea sp),
    CheckMapGrowLimit 1208:0EA5, PopPalette 1090:02DF and ShowSpecialistSizeMessage 1030:8934.
  - Count: 37 descriptors list FRR_DS.
    - 4 are genuine: __StructCopy, movmem 1000:2A36, _qsortExchange 1000:30E7 (pops at 3109)
      and _Win87emExceptionCallback 1000:4198/41A5.
    - 33 are wrong:
      - 31 game functions: 4 with {DS}, 8 with {SI,DS} and 19 with {SI,DI,DS}. They are
        ApplyGlobalWarming, ShowSpecialistSizeMessage, ShowTextByName, TextBoxSetup,
        PushPalette, PopPalette, InitGodPalette, FreeGodPalette, GR_PortDataToBitmap,
        PicDecompress, LoadAdvisors, CivLoadGame, RLLDecode, RLLEncode, HandToHand, NewPtr,
        DisposPtr, ShowConquerorEnding, OpenResFile, OpenResFileStdio, DisposeResourceMgr,
        NewResource, AddType, AddRFileFromStream, AddRFileFromImage, PortTileBlt, WdwMapOpen,
        CheckMapGrowLimit, WdwSmMapOpen, DrawSmTiles and WdwStatusOpen.
      - 2 run-time functions: getcurdir 1000:13A1 and tzset 1000:3BA8, where the push ds is
        getenv's argument.
    - 4 more have a wrong push_ds = 1: chdir 1000:116E, unlink 1000:19AA, _chmod 1000:1F60 and
      __DOScreate 1000:2AAF. Each does push ds, then pop ds after int 21h; the epilogue is pop
      bp; dec bp; retf (ret 6 for __DOScreate).
  - Consequence 1 — game functions: each of the 31 runs its whole body with SP 2 bytes lower
    than the original. Alternatively, if the translator drops the argument push, the callee
    gets one word short. Either way this breaks prompt 5.2 item 7: "moves SP by exactly its
    original frame … writes … its bytes in listing order".
    - NewPtr runs on every allocation.
  - Consequence 2 — emulated DS corruption in rt:
    - _chmod pops DS at 1F6E. Its error path 1F74 push ax; call __IOerror writes the DOS error
      code into [bp-2]. fr_leave (vm.c 477–479) then loads cpu.ds from [bp-2], which now holds
      the error code.
    - open() calls _chmod(path,0) at 1000:2B01 on every open. So every open of a file that does
      not exist yet takes this path: a new save, a missing famehall.civ, the replay file.
    - getcurdir (13B3), chdir (117D), unlink (19B9) and __DOScreate (2ABF) have the same flaw.
    - tzset reloads DS from [bp-8], which is overwritten by later pushes (for example 3C98 on
      the TZ-set path, which tests use).
- Fix:
  - Accept a prolog push as a frame save only if every return path pops it, in reverse order,
    directly before the frame teardown (lea sp,[bp-2], mov sp,bp, pop bp, or pop ds for
    push_ds).
  - Every other push is a body push: the translator, or rt, emits it with stk_push16 and the
    matching stk_pop16/stk_drop.
  - Make any mismatch an unexplained generator finding, regenerate, and write the rule into
    DESIGN 3.4.

### B2. BLOCKER: the never-reuse selector and handle allocators run out in ordinary play

- Where:
  - DESIGN 3.1 lines 105–107 and 3.6 lines 319–332;
  - vm.c vm_block_alloc 139–177 and vm_block_free 179–195;
  - prompt 5.2 item 5.
- What is wrong:
  - Dynamic selectors 0x1428..0x7FF0 give 3,450 values and are never reused.
  - Handle ranges, also never reused:
    - HWND from 0x2000: 2,048 ids;
    - HDC from 0x3000: 2,048 ids before the GDI range starts at 0x4000;
    - GDI from 0x4000 to 0xFFFE: 24,576 ids.
  - The game allocates and frees on every sprite draw.
- Evidence:
  - Prompt 5.5 requires the 256-colour palette path (g_noPaletteDevice = 0).
  - On that path DrawTileImpl 11A8:0F56 does:
    - 11A8:1287 call far NewPtr, which calls GlobalAlloc at 1100:05E6;
    - 129C CreateCompatibleDC;
    - 12BC CreatePortBitmap;
    - then 138E DeleteObject, 1396 DeleteDC and 13A1 DisposPtr (GlobalFree).
  - DrawTileImpl runs for every non-null tile that DrawTile draws. DrawTile has 22 callers,
    including DrawMapTile, DrawUnit and DrawTileOpaque.
  - So each sprite draw permanently uses up one selector, one HDC id and one GDI id.
  - After about 2,000 sprite draws there are no HDC ids left; after about 3,450 there are no
    selectors left. Then vm_block_alloc returns 0 and NewPtr returns NULL. The original never
    reaches that state: Windows 3.1 reused selectors and heap handles, as DESIGN 3.6 itself
    says.
  - Freed blocks also keep their host memory until vm_shutdown (vm.c 189–190), so memory grows
    without bound.
  - Nothing defines what happens when the HDC allocator reaches 0x4000.
- Prompt conflict: the prompt requires "Freed selectors are quarantined, never reused" and
  dynamic selectors "between 0x1420 and 0x8000". Both cannot hold for this program, so only the
  user can relax it.
- Fix — ask the user; propose a deterministic bounded quarantine:
  - Freed selector runs enter a FIFO.
  - A new block takes never-used selectors while any remain. After that it takes the oldest
    quarantined run that fits (first fit in FIFO order), and only once at least N later frees
    have happened (for example N = 256).
  - Release host memory when a run is freed or reused.
  - Record the policy as a choice plus a fidelity entry.
  - Use the same policy for each handle kind. The prompt only requires those to be non-zero
    and even. Use ranges that cannot collide.
  - Add a phase-2 test of about 10,000 allocate/free cycles.

### M1. MAJOR: C2 is misread, and the granularity choice makes reachable C2 masks fault

- Where: DESIGN 3.1 lines 109–117 and §10; prompt 5.3 lines 540–543; findings C2.
- What is wrong:
  - DESIGN says "the prompt states only 0xE5 and 0xE7 occur in play". The prompt actually says:
    "Masks 0xE5..0xE8 address the C1-written bytes … so only 0xE5 … and 0xE7 … occur in play".
    That restricts only the masks within 0xE5..0xE8. Because bit 0 is always set, every odd
    mask can occur.
  - findings C2: the mask starts as 0xFF >> (6 - numAi), which is 0xFF with six AI opponents.
    "for mask values of 0xE6 and above (civs 5, 6 and 7 all alive …) … up to 12D8:4643".
  - With limit 0x461F, the word read at 1030:298E faults for odd masks 0xEF..0xFF (0x4444 +
    2·0xEF = 0x4622). That happens whenever the rule runs (human spaceship started, earlier
    triggers failed, 1030:296B..2987) with most civs alive, so the port would show a general
    protection fault in such late games.
  - The evidence plan is also weak:
    - DESIGN plans to confirm the 32-byte granularity with the oracle-memory grant.
    - The oracle is "original under OTVDM on Windows 11", and that grant only snapshots segment
      images.
    - Neither establishes a Windows 3.1 descriptor limit.
- Fix:
  - Correct the text.
  - Before phase 2, decide between two options:
    - (a) keep 32 bytes and send masks ≥ 0xEF to the fault policy, with a fidelity entry and
      the prompt-7 "C1/C2 bytes" test;
    - (b) adopt a sourced Windows 3.1 rule that admits 12D8:4643.
  - Label any OTVDM observation as OTVDM behaviour.
  - Add the reachable C2 masks to inventory/out-of-range.md.

### M2. MAJOR: stack writes inside function bodies (temporaries, spills, register copies) are
not part of the core call model

- Where: DESIGN 3.4 lines 199–219 and §7 lines 418–421.
- What is wrong:
  - The model covers argument pushes, prologs, the F_SPUSH residue and adapter extras.
  - The listing also pushes non-argument values inside bodies. Those words stay below SP as
    stale values for later frames, which rule 6.6 class (a) depends on. Prompt 5.2 item 7:
    "Stale values left by earlier calls are then where the original left them".
- Evidence:
  - Game segments contain 137 pop dx, 121 pop eax, 81 pop es, 64 pop bx, 56 pop ax and 11 pop
    edx.
  - Examples:
    - push dx; push ax; pop eax at 1030:0139 (ProcessCity), 1130:011A (ChooseFileToOpen) and
      1208:0EFC (CheckMapGrowLimit);
    - 1008:0FE1..0FE3 does the same before the deferred add sp,4 at 0FE5, overwriting the area
      time()'s frame used;
    - 1030:97BD..97CA (DrawArrowButton): push dx … push ax … pop dx; imul dx; pop dx.
  - rt already follows this rule: rt_int.h lines 4–8 say "the same extra pushes and pops inside
    the body". DESIGN does not state it for core.
- Fix:
  - State that every body push and pop is emitted at its listing position with the listed
    value (stk_push* / stk_pop16 / stk_drop).
  - Include these in the translator's push matcher and in the phase-3 last-writer analysis.

### M3. MAJOR: the checked build only checks whole objects; per-index and member overflows go
unseen

- Where: core/acc.h lines 67–107; DESIGN 3.2 lines 165–173; prompt 5.2 item 3.
- What is wrong:
  - ACC_CHK compares an address only with [VA_g, VA_g + SZ_g) of the whole global.
  - Dimensions and member arrays are not checked.
  - F_RD/F_WR/F_RDX/F_WRX have no check hook at all. DESIGN says "the translator adds ACC_CHK
    for indexed pointer accesses", but the address is computed inside F_RDX, so the translator
    cannot reach it.
- Evidence:
  - g_units is 0x3000 bytes with strides GS 0x600 and GS2 0xC.
  - U3 g_units[civ][-1] (1188:013F) stays inside g_units for every civ ≥ 1, so it is never
    logged; neither is g_units[civ][128] (11F0:08DA) for civ < 7.
  - A member-array overflow inside g_cities is never logged either.
  - The allowlist therefore cannot separate known sites from new ones introduced by
    translation errors.
- Fix:
  - Have layout.py emit per-dimension element counts (for example GN_/GN2_/FN_).
  - In the checked build, check each index against its dimension, still without changing the
    access itself.
  - Add checked forms for pointer-based accesses.

### M4. MAJOR: structures passed by value have a contradictory parameter model

- Where:
  - DESIGN 3.4 line 197: "structure by value→vptr_t of the source";
  - gen/porttypes.py lines 10–12 and 87–93;
  - civ_core.h lines 99, 100, 102, 298, 385, 732 and 775.
- What is wrong:
  - In the original, the callee works on its own copy at [bp+N], written by the caller through
    F_SPUSH or push dword.
  - DESIGN makes the C parameter a pointer to the caller's source object.
  - The porttypes docstring says the callee's prologue makes the copy. It does not: F_SPUSH
    runs in the caller.
  - push_expr emits stk_push_struct, which does not exist.
  - Reading members through the source pointer gives wrong bytes if the source changes while
    the callee runs. Possible case: RunTextInputDialog's two RECTs across its input loop. To
    confirm, check whether RunNewGameSetup writes those rects during the loop.
- Evidence:
  - DrawArrowButton uses lea ax,[bp+rc] at 1030:96CB, 96D9, 96F2 and 9711. It passes the
    address of its own copy to FillRect, FrameRect and F_SPUSH.
  - WdwMapProc 1208:01D7 uses push dword ptr es:[g_lastMouseLParam] for
    UpdateMapMoveCursor(POINT), with no F_SPUSH.
  - Scope: 7 live functions with 8 parameters — DrawArrowButton, DrawExitButton,
    DrawButtonBevel, FindNearestPaletteColor, EraseRect, UpdateMapMoveCursor, and
    RunTextInputDialog (two parameters).
- Fix:
  - A by-value structure parameter is always stack-resident: reads, writes and & all use
    FR_PTR(bp,+N).
  - Drop the C parameter, or keep it only for the checked-build comparison.
  - Call sites emit the listing's push form.
  - Fix the docstring, and remove or define stk_push_struct.

### m1. MINOR: the cs: claim in DESIGN §0 (lines 40–41) is false

- Game segments have 87 cs:[…] operands:
  - 63 jmp word ptr cs:[…];
  - 24 mov ax, word ptr cs:[bx] sparse-switch value scans (1048:01EA "search the 68 command
    ids at cs:03D8", 1030:9C38, 1058:06C9, 11F0:0D0C/1C18/39F7, 1220:12A7 and others).
- "No CS-relative data read exists outside segment 1000" is therefore wrong. At run time the
  scans are harmless as long as the translator turns them into C switch statements.
- Fix: correct the text and state that rule.

### m2. MINOR: vm_block_alloc can hand out the scratch selector 0x7FF8

- The check g_next_dyn_sel + ntiles*8 > 0x8000 (vm.c 150) accepts 0x7FF8, which DESIGN 3.1
  reserves as the scratch selector.
- It also overwrites the slot without checking that the segment kind is FREE.
- Fix: cap dynamic runs below 0x7FF8 and assert FREE.

### m3. MINOR: the tail-jump stubs write and _readEntry have ordinary FR_NONE far descriptors

- Affected: write 1000:402D (jmp __write, civ_frames.c 124) and _readEntry 1000:3493 (jmp
  read, line 106).
- If rt calls fr_enter for the stub and then again in the jump target, the return address is
  pushed twice and the target's frame lies 4 bytes too low.
- Fix: add a no-frame jump kind, or document it.

### m4. MINOR: the checked build does not restore vm_site after a call

- After a callee returns, an out-of-object hit later in the same caller statement is logged
  under the callee's last site (vm.h 83, acc_chk). It can then merge into an allowlisted (site,
  object) record and be masked.
- Fix: restore the caller's site after each call.

### m5. MINOR: accessor details

- va_ix and va_ix2 take an int32_t index (acc.h 55–65). Passing an unsigned long index above
  INT32_MAX is an implementation-defined conversion. Use uint32_t; the result is unchanged.
- G_IX checks a width of 1 (line 79). A one-past-the-end address such as &g[n], legal C and
  used as a loop bound, is logged as out of object.
- In G_WRX, GF_WR and F_WRX, the address and the value are two arguments of one mem_wr* call.
  Their order is unspecified, and side effects in both are unsequenced (undefined behaviour).
  Document that rule 6.4 linearization applies.
- The tag tokens (A, S, FP, NP, I8, …) are bare identifiers that pass through macro expansion.
  Any macro with the same name in core breaks every accessor. Prefix them.
- #if CIV_CHECKED (acc.h 68, civ_api.c, rt_int.h 36) does not match #ifdef CIV_CHECKED (vm.c
  362).
- DESIGN §1 (lines 62–64) claims civ_headers.c expands every accessor form. G_RDX2, G_WRX2,
  GF_RD2 and GF_WR2 are never expanded (civ_headers.c 41–53), so the language checks do not
  cover them.

### m6. MINOR: the vm_fault contract

- The vm.h comment (74–76) says vm_fault returns if the handler returns. In fact it always calls
  host_fault, which does not return (host.h 20).
- If it ever did return:
  - mem_host(p, n>4) would hand out the 4-byte g_dummy buffer (vm.c 220–246, 286–289);
  - disp_call_* would call through a null entry (civ_dispatch.c 126–178).
- Fix: document vm_fault as non-returning, and make those fallbacks safe or remove them.

### m7. MINOR: floating-point decisions are missing

- porttypes maps long double to double unconditionally. Prompt 5.4 allows that only with a
  recorded exactness proof for 1068:1004 and 1190:074A/1B00/1B89/1C12.
- There is no encoding rule for double arguments pushed on the stack. Example: pow at
  1190:1ADF..1AF4 via sub sp,8; fstp qword ptr [bp-0x1C].
- There is no decoder for float constants, and acc.h has no F32/F64 accessor forms.

### m8. MINOR: handle and naming details

- Window-less timer ids "1, 2, …" (DESIGN 332) include odd values. The prompt (lines 464–467)
  lists timer ids among the values that are "never 0, even".
- The core function WinMain (civ_core.h 12, 1008:0000) has the same external name as the win64
  host entry, which gives a duplicate symbol at link time.

### m9. MINOR: phase-1 decisions that are missing or not listed as open

- The DGROUP instance header 1420:0000..000F (where InitTask writes, per data-structures.md
  122–123) is neither written by the replacement start-up nor masked.
- The placement of the PSP and environment block (_psp 1420:0016, _pszCmdline 001C) is not
  decided; it affects the selector allocation order.
- The step watchdog (prompt 5.3 "Hangs" and the §7 harness) is not designed.
- The world-generation state injection at 1028:0100 (prompt §7 "Seeds") is not designed.
- The GlobalAlloc limit (CheckMapGrowLimit probes up to 4,096,000 bytes) and Q16 are not
  recorded.
- Q5, Q6, Q7, Q8, Q10, Q11/H29, Q12, Q17 and Q22 are not listed with an owning phase.
- §8 has no notes for the picture codec (10B8), the god-palette reserved ranges or 16-colour
  dithering.
- §9 does not mention frame hashes.

### m10. MINOR: NE loader robustness

- 1u << align (ne.c 84) and 1u << rd16(...) (148) shift by values read from the file; a value
  of 32 or more is undefined behaviour.
- Entry-table reads data[p+1], data[p] and data[p+3] (121, 132–133) and ne_reloc's
  data[p]/data[p+1] (203–204) are not bounds-checked against size.
- An unresolved movable entry leaves target segment 0, and 0x1000 + 8*(0-1) wraps (331).
- All of this is safe only for the hash-verified civ.exe. Fix: check the hash before ne_parse,
  or bound every read.

### m11. MINOR: documentation drift

- DESIGN §4 (348–351) and STATUS 66 still say "51 rt entries". rt_api.h now has 155, of which
  117 are still stubs.
- DESIGN §4 does not mention register inputs of helpers (the __StructCopy CX count).
- The vm.h comment at 167–169 refers to DESIGN §8 for the ES approximation, but §8 says nothing
  about ES.
- vm.h 127 labels mem_copy as "(SCOPY@)". SCOPY@ copies words, then a final byte; on
  overlapping ranges the results differ.
- DESIGN §6.3 gives "Button" a 50 µs cost. Button (1100:0A5D) is game code whose only API call
  is PeekMessage at 1100:0A94.

### Notes

- N1. pop cx epilogues and local discards (Button 1100:0AA2, MapDistance 11C8:02EC) leave a
  local's value in CX, and fr_leave does not set cpu.cx. This matters only if a caller reads CX
  afterwards (rule 6.6 class (c)).
- N2. In callback frames, the saved DS and saved BP words came from USER in the original; the
  port writes its own values, and all pushed segment words are virtual. Extend the fidelity
  entry for return-address segment words to cover these.
- N3. Possible: Windows 3.1 enhanced mode may give the tiles of a huge block selector limits
  that run to the end of the block. In that case a word access at offset 0xFFFF of a non-last
  tile would not fault in the original, but it faults in the port. To confirm, use KERNEL
  documentation; OTVDM behaviour is not Windows 3.1.
- N4. Resolved during the review:
  - rt___StructCopy(uint32_t ra, vptr_t dst, vptr_t src, uint16_t size) now carries the CX
    count (rt_api.h 46; rt_helpers.c follows 1000:137F..1394).
  - rt_F_SPUSH matches 1000:14F8..1518: it leaves the return address, DI and DS below the copy,
    with AX = the advanced source offset and BX = ES = SS.
- N5. DESIGN §8 bounds host stack depth by the 9 KB emulated stack. Host frames of the giant
  functions are much larger than their emulated frames, so measure the deepest nesting and set
  /STACK to match.
