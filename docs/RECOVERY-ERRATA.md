replacement): translate.py's `line_string_addr` reads a literal's source line from the unpatched
file at the patched line number, so a replacement that changes the line count would resolve the
string literals that follow it in the same file, and in the other units translated from that file,
against the wrong line (round 5 found such a shift: E14 without padding changed
DrawCityScreenTitle's literal at 1030:8BD0 from DSTR(0x06C0) to DSTR(0x06B9)). E2..E6 change the
line count; a `--show` translation of their units with line-count preserving padding gives the same
`DSTR` sequence as the current units (`docs/verify/round5-fixes.md`), so they are left as they are.
