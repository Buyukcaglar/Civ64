## What was built

* **The store** `present/dos/` (portable C, in the language-checked loop of `build.cmd`):
  `pdos_assets` (activation all or nothing, status, message, file ids, accessors), `pdos_exe` (MZ,
  EXEPACK in place, packed relocations, the 23 overlays, `CIV_UNP.EXE`), `pdos_pic` (chunks, the DOS
  LZW R:0000:1318 and RLE R:0000:12BC, X0/X1 rows, palettes), `pdos_font` (`FONTS.CV`, G#4, G#12, the
  row words), `pdos_text` (the "rt" records, the read-only section lookup R:1F4D:01AD), `pdos_tables`
  (registry resolution and validation), `pdos_shapes` (the start-up cut O5:1455, the unit recolouring
  O5:1A14..1ADB), `pdos_common.h`, and `pdos_registry.h/.c` generated by `gen/dos/registry.py gen`
  from `tests/dos-files.txt` and `docs/dos/OFFSETS.md` (a `build.cmd` step; written only when changed).
* **The read service** `host_dos_read` / `host_dos_where` (`platform/w16/host.h`): Win32
  (`hw_set_dos_source`: a folder through `hw_find_name`, read-only `CreateFileW`; a ZIP held in memory by
  phase R) and headless (`hh_set_dos_source` folder or `.zip`, `hh_set_dos_zip`, `hh_dos_inject`). Harness
  options `--dos-data DIR|ZIP` and `--dos-inject NAME:missing|size|error|flip`; the harness activates the
  store before `vm_init` and writes `dos-assets.log`.
* **civ64**: after `civ64_open_data`, a DOS folder equal to the data directory is refused with exit 2
  (`civ64_dos_dir_ok`, E.3.3, E.18-1; inside is accepted), then `hw_set_dos_source` and the one call of
  `pdos_assets_open()` before the window and the emulation. The status and the one-sentence message are
  kept for the profile switch (RV1-6, RV1-8: the chord's message is D3's). Without DOS files the status is
  `PDOS_E_NONE` and nothing else changes.
* **Files and tools**: `tests/dos-files.txt` (158 required files, 1,918,109 bytes; `CIV_UNP.EXE`
  optional; the two derived hashes), `docs/dos/OFFSETS.md` (11 registry rows), `gen/dos/registry.py`
  (`pins`, `gen`, `goldens`, `check`), `gen/dos/shapes.py` (independent cut model), `gen/dos/nodos.py`
  (`check`), `tests/dos-decoded.txt` (1,330 golden lines from the Python models).

## For the records

The orchestrator applies these; D2 did not edit the files.

* **DESIGN.md** (new subsection "DOS assets at run time", 12.5 or as numbered): the store
  `present/dos/` (modules as above; portable C; built once per process before the emulation, all or
  nothing; allocation-free accessors; diagnostics), the read service `host_dos_read`/`host_dos_where`
  (Win32 `hw_set_dos_source`, headless `hh_set_dos_source`/`hh_set_dos_zip`/`hh_dos_inject`), the
  civ64 call site and the data-directory rule, the generated `pdos_registry.h/.c` (`build.cmd` runs
  `registry.py gen`), the pins `tests/dos-files.txt`, the registry `docs/dos/OFFSETS.md`, the goldens
  `tests/dos-decoded.txt`, the checks `registry.py check` and `nodos.py check` in `test.cmd`, the
  shared `hw_find_name` and `zip_find_base`.
* **FIDELITY.md** (new rows): (1) a DOS folder inside the data directory is accepted, equal is refused
  (E.18-1); (2) DGROUP:1A3E taken as 0: terrain rows 0..5 get all 16 variants (DOS with little free
  memory would cut one; E7); (3) every `G#2` grab succeeds (the arena-full case is not modelled; E8);
  (4) shapes are full w x h arrays with 0 transparent (DOS stores trimmed rows; equal drawing);
  (5) stale DOS reader state is refused, not modelled (a second `M0`, short `M0`, a first LZW code
  above FFh after a start or reset, an expansion through the stale entry 100h, a code in a missing
  byte, chunks over 6,144 bytes): a picture decodes the same in any order; (6) texts: a name whose
  group reaches the end of the file shows nothing (DOS would not return), a text reaching it is
  refused, more than 256 index probes fall back to the scan; (7) a read may update a file's
  last-access time on volumes that keep it (E5, host fact); (8) `CIV_UNP.EXE` is accepted in place of
  `CIV.EXE` (headless, and from a ZIP; phase R's own check still asks for `CIV.EXE`).
* **RUNNING.md**: the harness options `--dos-data DIR|ZIP` and `--dos-inject NAME:missing|size|error|flip`
  and `dos-assets.log`; `test.cmd` requires `build\dosdata` (the DOS copy, read only) and runs
  `test_dos`, `w32_test_dos_host`, `registry.py check` and `nodos.py check --variant`;
  `registry.py pins|gen|goldens|check`, `shapes.py goldens|view`, `nodos.py check`.
* **STATUS.md** (extension track): D2 complete in Checked and Release on 2026-10-11 (this record);
  Asan deferred to the final pass with `test_dos`; open for D3: the profile's use of the status and
  message (RV1-6, RV1-8), `--graphics dos` failing with exit 2 (E.3.3 step 3), "Locate during a run"
  (E.13.3), the full DOS variations of 7.3/7.4 in A's runner; E2..E8 of the design's open list stay open.

## Not verified

* Asan builds and tests (deferred).
* civ64.exe was not started: the activation path in `civ64_main.c` is compiled and its parts are
  tested (the read service, the data-directory rule, phase R's locate tests, the store); its start
  with and without DOS files, and the exit-2 message box, were not observed.
* "Locate DOS files..." during a run (E.3.6, E.13.3): area A's handler does not exist yet (D3).
* The ZIP source in civ64 itself (phase R reads it into memory and hands it over): tested through
  `hw_set_dos_source` with ZIPs made by the test, not through a real `CivDos.zip` start.
* Cold-disk activation time; Asan's view of the malformed-input and bit-flip runs.
* No DOS behaviour was observed (no DOS-oracle run): the goldens agree with the Python models, which
  D0 checked against the listing, not with a running DOS program.
