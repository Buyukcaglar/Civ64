## 11E8:0DCF GetScreenBufferPixel — PASS

**Compared** [L][M][S]:
* **Frame:** FR_WIN_FAR with `push ds`, no locals, no saves, argbytes 4, far return (`retf`). This matches 0DCF..0DD7 and 0E15..0E18.
* **Argument checks:** `CX_CHK16` of x at bp+6 and y at bp+8.
* **Registers:** x (DX) and y (CX) are not SI/DI and stay C parameters. The function never writes SI/DI, so no register-variable binding applies.
* **Bound tests** (l.22, marker 0DDF), signed, in listing order: `or dx,dx; jl`, `cmp dx,0x140; jge`, `or cx,cx; jl`, `cmp cx,0xc8; jge`.
* **Out-of-range path** (marker 0E11, l.23-27): returns 0. AX = 0x1400 (`ret_ah` "0x14u").
  * Listing: AX = DS from `mov ax,ds` (0DCF); 0DD9..0DF1 write only DX, CX and flags; 0E11 `mov al,0`.
  * AH is therefore the high byte of DS: 0x14 with the port's DGROUP 0x1420.
* **In-range path** (marker 0DF3, l.29-33):
  * The byte is loaded at `va_ix(g_lpScreenBuffer, U16(U16(y*0x140)+x))`: selector of `g_lpScreenBuffer`, offset (OFF + y\*0x140 + x) mod 0x10000, without carry. This equals the listing's `movsx eax,cx; imul eax,eax,0x140; add ax,dx; mov es,[B396]; add ax,[B394]; mov al,es:[bx]`, whose `imul` is used only through its low word.
  * AX = (low word of y\*0x140 + x + OFF) with AL = pixel (`ret_ah` second entry). The listing's AX after 0E0A is exactly that sum with AL replaced, and the 0E0D/0E15 epilogue does not write AX.
* **`ret_ah` order:** source order, out of range first, then in range. This matches the C's two `return` statements.
* **Return value:** a `uint8_t` on both paths. The `cpu.ax` write precedes `fr_leave`, and the returned temporaries (t_1, t_2) are not register variables.
* **Unreachable bytes:** the two bytes at 0E0F are not translated, which is correct.
* **Consumers of AH** [C]: every caller that uses the whole AX zero-extends AL first with `mov ah,0` (e.g. 1110:170D, 11F0:2D35, 10E8:173B, 1078:1F87, 1040:04C9, 11C0:27BF). The only exceptions are the whole-AX byte-argument pushes (earlier report: 1028:09C7, 1110:192B, 1964, 1A50, 1A74, 1ABF, 1170:04C3), which the `ret_ah` annotation serves.

**Findings:**
* **N1 (NOTE, carried and reduced):** at return the listing leaves CX = y and DX = x (0DD9/0DDC). The port does not set `cpu.cx`/`cpu.dx`.
  * [C] No caller reads CX before writing it: no CX/CL/CH use follows any call.
  * DX is read only after a write: `mov dx,seg ...`; `mov dx,[bp+bits]` at 1110:1AD6/1B8B; `mov dx,ax` at 1110:19D3/1A22.
  * Not observable, which agrees with DESIGN.md 3.4: registers are kept only where a caller reads them.

## 11E8:0E19 SetScreenBufferPixel — PASS

**Compared** [L][M][S]:
* **Frame:** FR_WIN_FAR with `push ds`, one SI save (FRR_SI, 0E23; epilogue `pop si` at 0E5B before `pop ds`), argbytes 6, no locals.
* **Argument checks:** `CX_CHK16` of x (bp+6) and y (bp+8); `CX_CHK8` of color (bp+0xA, low byte only).
* **Register parameter:** y is bound to SI from 0E27 on (DESIGN.md 3.4, "register parameters"). The load is emitted at the start of the body (l.44), after `fr_enter` has saved the caller's SI, so the save holds the caller's value as `push si` (0E23, before 0E27) does. `fr_leave` restores SI from that slot, so callers see their own SI.
* **Bound tests** (l.46, marker 0E2A), signed: `or cx,cx; jl`, `cmp cx,0x140; jge`, `or si,si; jl`, `cmp si,0xc8; jge`, all to the epilogue at 0E5B.
* **Store** (l.52, marker 0E3E): the low byte of `color` at (OFF + W(SI\*0x140) + x) mod 0x10000 through the selector of `g_lpScreenBuffer`, as 0E3E..0E58 does (DL = color at 0E53).
* **`ret_ax`**, per return in source order, then the end:
  * Clip return (l.47): 0x1420, the AX = DS of `mov ax,ds` at 0E19. 0E24..0E3C write only CX, SI and flags.
  * End (l.53): low word of SI\*0x140 + x + OFF. That is the AX of 0E3E..0E4F; 0E53..0E58 write DL, BX and memory.
  * Both match the listing.
* **AX consumer** [L]: ComputeCitySiteValues 1028:123B call; 1240 `add sp,6`; 1243 `mov al,[bp+squareValue]`; 1246 `push ax`. The generated push (`seg005_1020.c` l.1514) takes AH from `cpu.ax`, which l.53 sets.

**Findings:**
* **N3 (NOTE, new):** at return the listing leaves CX = x, and on the store path also DL = color (DH is the caller's). The port does not set `cpu.cx`/`cpu.dx`.
  * [C] After every SetScreenBufferPixel call site, the only CX/DX instruction within six instructions is `pop cx` (a write; e.g. 1028:0A4D, 1110:1762, 1110:17B7).
  * Not observable.

## RECOVERY

None [L]. The recovered C matches the listing:
* the signed range checks;
* the 16-bit index `(unsigned)y*0x140u + (unsigned)x`, equal to the listing's low word of the 32-bit product plus x for all inputs;
* the 0 result outside the buffer and the ignored write outside it.

The listing headers' register notes (none for GetScreenBufferPixel; `si = y` for SetScreenBufferPixel) agree with `names.json` `register_vars`.
