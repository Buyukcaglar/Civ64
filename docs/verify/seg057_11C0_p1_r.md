**TRANSLATOR T1 (11C0:0ED4; lines 50-51, 237).** The register parameter `unit` is loaded into
SI at 0ED4 (`mov si,[bp+unit]`), in the straight entry block, and SI keeps that value until
123B. The generated C binds only DI (l.51 `REG_DI_I16 = civ;`) and reads `unit` as a plain C
parameter; `cpu.si` keeps the caller's SI (MoveCivUnits holds the unit in DI and something else
in SI, 11F0:090C) until l.237 writes the FindCityAt result. DESIGN.md 3.4 "Register variables"
requires a parameter that the listing's first write of SI loads to be read and written through
the register from that point on. Every SI-saving callee frame therefore stores a different
saved-SI word into the emulated stack than the original (5.2 item 7): UpdateGameMenus (0F29,
always reached), UpdateOrdersMenu (0F30), PollMouseClick (every loop pass), RestoreBlockXY,
DrawUnit, PlotSmMapSquare, DrawTextAtPortXY, SetCivFont, GetTileImprovements. Same class as
verify/seg045_1160_p1.md T1. The function's own epilogue restores the caller's SI in both
programs, so only the stale stack words differ. Required: bind `unit` to SI at 0ED4 (emit
`REG_SI_I16 = unit;` with the 0ED1 load and read SI wherever the listing does), as the
translator does for x/y in AddUnitToTile and civ/unit in FindNextNonShipUnitInStack.
Probable root cause (not read in the translator): SI is already bound to the register local
`cityIndex` (recovered line 447), so the 0ED4 parameter load is treated as covered, the pattern
of seg045_1160_p1.md T1.
