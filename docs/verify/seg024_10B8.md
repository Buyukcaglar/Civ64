* **NOTE N6 (new): out-of-range sites for the out-of-range inventory** (brief: "report any you
  find"). The port follows the listing at each site. The table block is GlobalAlloc 0x6000 at
  offset 0: prefix +0x0000, suffix +0x2000, length +0x4000. [L][C] All of the following need corrupt
  or unusual picture data.
  * **(a) Writes indexed by nextCode2 ≥ 0x2000** (minCodeSize 10 or less, so codeWidth grows to
    12 and stops). C15: "at code width 12 without a clear code new entries are written beyond the
    three 4096-entry tables".
    * The writes are 1944 `prefix[nextCode2]` (line 763), 194F `length[nextCode2]` (line 764),
      1951 `inc length[nextCode2]` (lines 765-766) and 1AEC `suffix[nextCode2]` (line 835).
    * At nextCode2 = 0x2000, 1944 writes into the suffix table and 194F/1951 write at offset
      0x6000, outside the block.
    * 1AEC writes into the length table and leaves the block at nextCode2 ≥ 0x4000.
    * So 194F, in the first pass with nextCode2 = 0x2000, is the first access outside the block.
    * Every read before it stays inside its table: code2 is masked to 0x1FFE or less, and the
      chain values are such codes.
    * C15 names only 1AFF (the missing guard) and 1ADA, so these four access sites have no
      comment.
    * Suggested: `MANUAL` entries (C15, OOB) and inventory/allowlist entries.
  * **(b) Root-entry loop with minCodeSize 11..14** (16BD, 16D9, 16E6; lines 646-648). The loop
    bound is the pre-multiplied nextCode2 = `(2 << minCodeSize) + 4`, used as an entry count.
    * For minCodeSize 11 that is 0x1004 entries. From entry 0x1000 on, 16BD writes into the
      suffix table and 16D9 into the length table.
    * 16E6 writes at offset 0x6000, outside the block, as the first such access (entry 0x1000).
    * The listing's own note calls the doubled loop harmless; that holds only for minCodeSize up
      to 10.
    * minCodeSize comes unchecked from the picture header (LoadGifPicture 123E, hdr[4]).
    * No finding describes this case, so a findings.md entry would be needed before a comment.
  * **(c) Unbounded input.** Neither function has a source size, so a truncated stream (one that
    ends without an EOI code) is read past the resource block by 179F and 17D2 (lines 691, 696).
