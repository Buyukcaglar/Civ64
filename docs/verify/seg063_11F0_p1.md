### Findings

* **R6-T1 TRANSLATOR (rule 6.6 class and the rule-6 last-writer record; DESIGN.md 3.4 row) — a
  Windows API frame can be the last writer of bp-0x24 at 11F0:13BF, so the site is class (b), not

  * [L] ProcessGameTurn always calls CheckLowResourcesWarning at 1088:01B1 and reaches it from 015E
    (`jne`), 01A5 (`jle`) and the fall-through after 01AC. Only 01B6..01C3 (no call; `push [bp+i]`)
    run before `call far MoveCivUnits` at 01C6.
  * [C] Let S be the SP at 01B1. Then 01C3 pushes to S-2 and the far return address occupies
    S-6..S-3. MoveCivUnits' `inc bp; push bp; mov bp,sp` gives BP = S-8, so bp-0x24 = S-0x2C.
  * [L][C] CheckLowResourcesWarning (11E8:0075) has BP = S-6, then `push ds`, `sub sp,4` and SI/DI
    (S-0x10).

      and put their return address at S-0x20..S-0x1D.

### Other reads of the stale word (brief item)

[L] The only `g_terrainTypes[terrainType]` accesses in MoveCivUnits are 13CB, 157C, 2AC5 and 2AE8
(index loaded at 13BF, 1570, 2ABA, 2ADD); the `g_terrainImprovementRules` (12B8) lookups are indexed

* 1570/157C ('r'): only through 14E2 (no label of 14E2..15EB is entered from before 14E2);
* 168D/17B3 ('i'): through 168A; the cancel path 167A -> 16F2 reads nothing and jumps to 1C03;
* 18DF/19D6 ('m'): through 18DC; 18CC -> 1915 reads nothing and jumps to 1C03;
* 0A75/0AA6 (mouse GoTo): through 0A1C; the paths that skip it (0A02/0A0B -> 0B51, 09F2 -> 0C51)

  1D7C -> 2E67, which zeroes the moves and jumps to 39EB without a read.

After 13BF the fortress path continues 13D7 -> 1C03 (or 13DC..1432 -> 1C03) -> 39EB -> 4053, with no
read of the word. So 13CB is the only `g_terrainTypes` access, and 13BF the only read, that can see
the stale word; the fixer's statement holds for the whole function.
