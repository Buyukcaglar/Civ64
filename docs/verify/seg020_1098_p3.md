### Translator `ret_dx` review [T]

* `st_Return` (l.3172-3196): for a value return the result is first copied to a temporary when it reads emulated state (l.3173-3177), then the AX/AH line is written, then `cpu.dx` from `next_ret_dx()`, then `fr_leave` and `return`. The DX write therefore cannot change the returned value or be undone by `fr_leave` (which restores only the frame and SI/DI).
* `next_ret_dx` (l.3198-3207) takes the entries in source order with the counter `_ret_dx_k`; `Fn` is created afresh for every function (l.4446, 4477, 4493), so the counter does not leak between functions. A surplus value return raises `XlatError`.
* A None entry writes nothing (DX as the last call left it), which is the third return here.
* A non-None entry on a 4-byte result raises (`ret_regs` already writes DX there); a 1- or 2-byte result is accepted, matching the key description (annot.py l.26-28).
* The count check after rendering (l.1593-1595) raises when the entries and the value returns differ. A void function never consumes `ret_dx`, so a non-empty `ret_dx` on one also raises: misuse cannot pass silently.
* The fall-off-the-end path of a value function (`render`, l.1643-1665) consumes no entry and returns the emulated AX/DX as left, consistent with "per value-returning statement". CivDialogProc does not fall off its end.
* Result: the code is correct for its documented contract. No finding.
